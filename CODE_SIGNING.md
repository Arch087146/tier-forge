# Code signing policy

**Free code signing provided by [SignPath.io](https://signpath.io), certificate by [SignPath Foundation](https://signpath.org).**

TierForge release binaries are signed through SignPath.io's free open-source
program. The certificate is issued to SignPath Foundation, which verifies that
each signed artifact was built from this public repository by the public GitHub
Actions workflow.

## Scope

The following release assets are signed:

| Asset | Signature |
| --- | --- |
| `TierForge.exe` (inside the portable ZIP and installed by the installers) | Authenticode |
| `TierForge_*_x64-setup.exe` (NSIS installer) | Authenticode |
| `TierForge_*_x64_en-US.msi` (MSI installer) | Authenticode |

`SHA256SUMS.txt` and the source archives generated by GitHub are not signed.

## How releases are signed

1. A tag matching `v*` is pushed to
   [`Arch087146/tier-forge`](https://github.com/Arch087146/tier-forge).
2. The public workflow
   [`.github/workflows/release.yml`](.github/workflows/release.yml) builds the
   application on a GitHub-hosted `windows-latest` runner.
3. The unsigned executable is uploaded as a GitHub Actions artifact and
   submitted to SignPath. SignPath signs it, and the signed executable replaces
   the unsigned one.
4. The MSI and NSIS installers are built around the signed executable, uploaded,
   and signed by SignPath.
5. The signed assets and `SHA256SUMS.txt` are attached to the GitHub release.

Local builds are never signed with the project certificate. Signing requests
require manual approval by a project approver.

## Privacy

See [PRIVACY.md](PRIVACY.md). TierForge does not include telemetry or
analytics, and it does not transfer data to any networked system unless the user
explicitly requests an AI or image operation.

## Verifying a download

```powershell
Get-AuthenticodeSignature .\TierForge_0.1.0_x64-setup.exe |
  Format-List Status, StatusMessage, SignerCertificate

Get-FileHash .\TierForge_0.1.0_x64-setup.exe -Algorithm SHA256
```

A signed release reports `Status: Valid` and a signer certificate issued to
SignPath Foundation. Compare the SHA-256 hash with `SHA256SUMS.txt`.

Until the SignPath application is approved, release assets are unsigned and
`Get-AuthenticodeSignature` reports `NotSigned`.
